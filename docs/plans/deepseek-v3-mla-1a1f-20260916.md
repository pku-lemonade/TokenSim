## 2. 测什么模型

主对象是 **V3 的一层 MoE transformer block**，保持真实宽度：

- hidden=7168，128 query heads；Q latent=1536，KV latent=512；noPE/RoPE/V=128/64/128。
- 256 routed experts、top-8、1 shared expert，expert intermediate=2048；BF16。
- A 侧运行 MLA，F 侧运行 Router 和专家；Combine 按当前 TokenSim 的 A 侧语义固定。保存这套分工，不将其称为某个真实推理引擎的完整执行路径。
- 使用固定随机种子的合成权重、输入和路由，不下载 671B checkpoint。专家全部属于这一层，总权重约 23 GB，F 单卡可容纳。
- 不包含 embedding、lm_head、采样、MTP 或语义生成质量；不仿真 noaux_tc 的分组选择。

**两张卡能测这一层，但不能常驻完整 BF16 V3。** 不通过关闭容量检查来生成“完整 V3 两卡结果”，也不把单层时延直接乘 61 当作完整模型性能。后续若研究全模型，需另行选择满足容量约束的虚拟拓扑；本方案不把 33 卡作为前提。

服务器实际显示每卡 81920 MiB（80 GiB），不能和旧实验的 80,000,000,000 字节混用。后续配置统一保存显存字节数；同时记录权重、KV、临时张量和 kernel workspace 峰值。

## 3. 第一阶段：算子补测与正确性

GPU 3 单独空闲时，可先完成单卡算子采集；此时不能声称完成 A/F 双卡流水验证。每项真实 GPU 工作执行前重新检查占用。

| 项目 | 首轮形状 | 目的 |
|---|---|---|
| Q/KV/O 投影、norm、RoPE | token 数 1、2、4、8、16、32、64、128 | 校准计算、访存与小批次固定开销 |
| Q absorption / value expansion | 同上，每卡 128 组 head | 测 grouped 执行，不相加 128 次独立启动 |
| compressed MLA core | batch=1、4、16、32；context=1K、4K、16K、64K | 校准 16 个主形状，检查 context 增长影响 |
| 独立验证点 | batch=2、8；context=8K、32K | 检查未参与拟合形状的公式误差 |
| Router、grouped experts、shared expert、Combine | token 数 1、4、16、32、64，保存专家负载向量 | 验证 MoE 组成和输出边界 |

先确认当前 A100/SM80 环境存在满足 `absorbed` 路径和本项目测量边界的 MLA kernel。若没有，先测可用的投影/grouped GEMM；核心保留明确标注的理论值。不得用展开 K/V 的 decode 或逐请求串行实现冒充压缩 MLA 的实测值，也不将它们塞进同一个 table key。

以小规模独立参考实现验证 absorbed/expanded 数学等价、batch 与逐请求参考一致、专家 id/权重及 Combine 结果一致。数值容差在采集脚本中预先固定并记录；超限的采样不用于校准。验证点不回填为同一轮拟合数据。

校准形式沿用 `T = 固定开销 + multiplier × max(计算时间,访存时间)`；按算子和执行方式拟合，报告误差。已有精确实测表项直接使用实测值，不再次添加理论开销。

## 4. 第二阶段：双卡通信与流水

GPU 2、3 都空闲后执行。先验证双卡 P2P/NCCL 路径和同一批输入的正确性，再采性能。

### 4.1 通信

测 A→F、F→A 的真实传输、启动延迟和同步；独立测量单向、反向、同时双向，不把 NV12 标签换算成已达到的带宽。

A→F 的基本 BF16 hidden tensor 为 `token_count × 7168 × 2` 字节；F→A 按当前 Combine 边界和实际 top-k partials/metadata 记录 payload，不能假定两方向相同。形状从真实 DAG/trace 导出。

### 4.2 固定总 batch，研究流水

| 固定项 | 取值 |
|---|---|
| 卡数/模型 | 1A1F，V3 单层 |
| Router / dtype / 路由 | F / BF16 / 固定路由快照 |
| 总 batch | 32 |
| context | 分别为 4K、16K |
| 唯一主自变量 | `af_batch_size = 1、2、4、8、16、32` |

共 12 个配置。`af_batch_size=32` 是不拆分基线。相同总 batch/context 下复用输入、权重和每个 token 的路由，只改变小批次划分。

对每点记录实际完成整批的 wall time、A/F 计算服务时间、通信时间、等待、空闲区间、计算重叠。主判据是相对不拆分基线的整批时延改善；重叠多不必然更快。

双卡真实验证使用一个对齐 TokenSim 边界的单层测试驱动，不引入 vLLM。如果没有完成这个驱动或核心 kernel 不可用，该阶段只能报告模拟结果，不称为双卡实测验证。

## 5. 第三阶段：画吞吐—交互速度折线图

固定 1A1F 和 `af_batch_size` 上限为 8，扫描并发请求数 **1、2、4、8、16、32、64、128**；context 分别为 4K、16K。并发少于 8 时自然形成一个小批次。

不要把并发度与 AF 小批次大小混为同一个变量，也不要在一条曲线中为每个并发点悄悄切换最优 AF 小批次。若另画逐点选优包络，必须标出每个点选用的小批次。

指标：

- 单层等效每用户 TPS = `1 / 本批所有请求完成一次层计算的时长（秒）`。
- 单层总处理速率 = `并发请求数 / 同一时长`。
- 单层 TPS/MW = `单层总处理速率 / ((P_A+P_F)/10^6)`。
- 每卡先按用户指定的固定功耗方式计算，默认 250 W/卡、总计 500 W，明确是可更改假设，不是本轮实测平均功耗。

**图中必须标注“V3 单层、1A1F、等效速率”**，不能把它当成完整模型生成速度。它只复用 NVIDIA 图的坐标形式；与 NVIDIA GPT-OSS-2T 全模型预测不作数值优劣比较。

首轮输出三张图：

1. AF 小批次大小 → 整批时延（4K/16K 两条线），直接回答流水是否有效。
2. 单层等效每用户 TPS → 单层 TPS/MW（固定 AF 上限 8），展示吞吐与交互的取舍。
3. 代表配置 `af_batch_size=32` 与最优实测/模拟小批次的 A/F 时间轴，展示等待与重叠来源。

## 6. 计时、profiling 与复现

- 默认 eager、关闭 CUDA Graph；若另测 Graph，使用独立运行标签和校准包，禁止混表。
- 每点预热至少 20 次；正式采集 3 个重复窗口，每窗口至少 100 次且持续至少 2 秒。长期运行时分块采集，避免小算子一次性记录过多事件。
- 正式计时关闭 profiler；GPU 区间和 host 整批 wall time 分开报告。双卡不能直接相减不同设备上的 CUDA event 时间戳。
- 独立 profiling 捕获代表迭代，统一 host 时间标记/通信依赖；保存 A/F kernel、memcpy/NCCL、队列和同步。若 CPU 导致 GPU 饥饿，单独报告，不能全归入 GPU 固定开销。
- 保存原始重复数据、P50/P95、GPU UUID/驱动/CUDA/kernel 版本、拓扑、显存峰值、温度/时钟、dtype、输入和路由快照、计时边界、运行命令。
- 保存真实 `A.trace.json`、`F.trace.json`，TokenSim `pipeline.trace.json`、逐算子表、source metadata、校准/验证误差和图表。模拟 trace 与实测 trace 明确分目录。
- 每个模拟点先离线发现 shape，再生成数据、正式查表运行；未测形状标明理论来源，缺失的 exact core shape 不做隐式回退。

## 7. 执行顺序与资源约束

1. 先在 CPU 上生成本方案的模型/shape 清单与理论基线；保留一个进程，必要时以低 CPU 优先级运行。
2. GPU 3 仍空闲时，先采单卡 MLA/专家算子；不触碰 GPU 0–2。
3. GPU 2、3 同时空闲时，测双卡通信并验证单层测试驱动。
4. 先执行 batch=32、context=4K 的 AF 小批次六点扫描，再补 16K。
5. 完成固定 AF 上限的并发曲线与误差报告；如核心 kernel 仍缺失，注明“部分校准”，不得宣布全部校准。

本轮不要求四张卡空闲，不申请完整 V3 的真实权重运行，也不自动启动 GPU 测试。当前 GPU 2 的训练必须自然结束后，才能执行目标两卡阶段。
